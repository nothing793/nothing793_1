# Task 1 （自出的题目）

## 题目：Two-Time Pad（流密码密钥重用攻击）

**题目来源**：课程 PPT [crypto-lec1](https://courses.zjusec.com/slides/crypto-lec1/) — 流密码与 XOR 密钥重用攻击

**知识点**：流密码中，若两次加密使用相同的密钥流，则 `c1 ⊕ c2 = m1 ⊕ m2`，攻击者可利用已知明文格式恢复密钥并解密。

## 1. 题目描述

> 流密码使用相同的密钥流加密了两段不同的明文，你截获了如下密文（hex 编码）：
>
> ```
> c1 = a427a79fc9bb4aca3895348fbc67938ffbccb3cb7995b5aa883eb3
> c2 = a124a89fc0ae49d0209d2d83a36884f1b2c683db3882a5b7d12eba
> ```
>
> 已知：
> 1. `c1` 的明文是纯英文小写字母 + 标点
> 2. `c2` 的明文以 `flag{` 开头，格式为 `flag{...}`
>
> 求 flag。

## 2.攻击原理

流密码加密公式为：

```
ciphertext = plaintext ⊕ keystream
```

当相同的密钥流 `key` 被用于两段明文时：

```
c1 = m1 ⊕ key
c2 = m2 ⊕ key
```

将两式异或，密钥流被消去：

```
c1 ⊕ c2 = m1 ⊕ m2
```

这个结果仅与两段明文相关。利用以下技巧可以恢复密钥：

1. **空格检测**：ASCII 空格为 `0x20`。当 `m1[i] = m2[i]` 时，`m1⊕m2` 在该位置为 `0x00`。若该位置是空格，则两段明文此处皆为空格。
2. **已知明文恢复**：已知 `m2` 以 `flag{` 开头，可直接恢复密钥的前 5 字节：`key[:5] = c2[:5] ⊕ b'flag{'`
3. **密钥复用**：恢复出的密钥对整段密文都适用，直接解密另一段密文可验证正确性。

## 3. 解题代码

```python
from pwn import xor
c1 = bytes.fromhex('a427a79fc9bb4aca3895348fbc67938ffbccb3cb7995b5aa883eb3')
c2 = bytes.fromhex('a124a89fc0ae49d0209d2d83a36884f1b2c683db3882a5b7d12eba')

m12 = xor(c1, c2)          # = m1 ⊕ m2
# 利用空格检测 + 已知flag前缀恢复密钥
key = xor(c2[:5], b'flag{')
# 剩余字节通过 c1⊕c2 和可打印字符约束恢复
for i in range(5, 26):
    for guess in range(32, 127):
        if 32 <= (c1[i] ^ guess ^ c2[i]) <= 126:
            m2_byte = guess
            key += bytes([c2[i] ^ guess])
            break
m1 = xor(c1, key)
m2 = xor(c2, key)
print(m1)  # congratulations! you did it
print(m2)  # flag{twotimepad_is_easyyyy}
```

## 4.输出结果

```
congratulations! you did it
flag{twotimepad_is_easyyyy}
```

## 5.Flag

```
flag{twotimepad_is_easyyyy}
```


# Task 2 Oneline Crypto（模算术与格）


##  1.题目描述

题目 Python 代码如下：

```python
assert __import__('re').fullmatch(r'SEE{\w{23}}',flag:=input())
and not int.from_bytes(flag.encode(),'big')%13**37
```

要求输入一个 flag：
1. 格式必须匹配 `SEE{\w{23}}`（即 `SEE{` + 23 个字母/数字/下划线 + `}`）
2. flag 的整数值模 `13^37` 必须为 0

## 2.问题分析

设 flag 的中间 23 字节为 `m_0, m_1, ..., m_22`，ASCII 值都在 `\w` 字符集中。\
`\w` = `[0-9A-Za-z_]`，共 63 个可打印字符。

flag 的整数值为：
```
flag_int = 83·256²⁷ + 69·256²⁶ + 69·256²⁵ + 123·256²⁴ 
         + Σᵢ₌₀²² mᵢ·256²²⁻ⁱ 
         + 125
```

记前缀 `prefix_int = 83·256³ + 69·256² + 69·256 + 123`，则：
```
flag_int = prefix_int · 256²⁴ + middle_int · 256 + 125
```

需要 `flag_int % 13³⁷ ≡ 0`，即：
```
middle_int · 256 ≡ -(prefix_int · 256²⁴ + 125)  (mod 13³⁷)
```

令 `d = 13³⁷`，`target_raw = (-(prefix_int · 256²⁴ + 125)) mod d`，\
`target = (target_raw · 256⁻¹) mod d`，则问题转化为：

**找到 23 字节 mᵢ ∈ \w，使 Σ mᵢ·256²²⁻ⁱ ≡ target (mod d)**

其中：
- `d = 13³⁷` ≈ `2¹³⁷`（137 bits）
- `middle_int` 是 23 字节 = 184 bits
- 搜索空间大小：`middle_int` 取 `target - k·d`，`k ∈ [-1.49e11, 0]`，共约 `2⁴⁷` 种可能

## 3.数学分析

### 3.1平均解个数估计

对于均匀分布在 `[0, 2¹⁸⁴-1]` 的整数，其 23 个字节全在 \w 中的概率为 `(63/256)²³ ≈ 2⁻⁴⁶`。\
而 `k` 范围为 `2⁴⁷`，所以期望解个数为 `2⁴⁷ · 2⁻⁴⁶ = 2`。

**平均有 2 个解**，搜索空间约 `2⁴⁷`，直接暴力不可行。

### 3.2低字节残基类加速

记 `256⁵ = 2⁴⁰`。因为 `gcd(d, 256) = 1`（d 为奇数），所以 `gcd(d, 256⁵) = 1`。

对任意 k，中间整数的低 5 字节为：
```
low_5 = (target - k·d) mod 2⁴⁰
```

由于 `gcd(d, 2⁴⁰) = 1`，k 模 `2⁴⁰` 与 low_5 一一对应。\
因此，**k 的残基类与低 5 字节的值构成双射**。

对于任意固定的低 5 字节组合 `(b₁₈, b₁₉, b₂₀, b₂₁, b₂₂)`，k 模 `2⁴⁰` 的残基唯一确定。\
k 的范围为 `[-1.49e11, 0]`，即约 `2⁴⁸` 个值。在每个残基类中，有约 `2⁴⁸ / 2⁴⁰ = 2⁸ = 256` 个 k 值。

**有效的低 5 字节组合数**：63⁵ ≈ 9.9×10⁸。\
**总检查数**：63⁵ × 256 ≈ 1.34×10¹¹。

这虽然仍很大，但已从 2⁴⁷ 缩小到可管理的 ~1.3×10¹¹。

## 4.解题

### 4.1 算法思路

1. 枚举所有 63⁵ 种低 5 字节组合（63 种字符 5 个位置）
2. 对每种组合，计算低字节整数值 `low_int = Σ bᵢ·256⁴⁻ⁱ`
3. 计算对应的 k 残基：`k_res ≡ (target_low - low_int) · d⁻¹ (mod 2⁴⁰)`
4. 在该残基类中迭代 ~256 个 k 值，对每个计算完整 23 字节并检查是否全在 `\w` 中


### 4.2解题代码

>完整的c代码见附件 ，这里仅展示比较重要的步骤
为加速 `middle = target - k·d` 的计算，将 d 和 target 分解为 184-bit 的 3×uint64 表示：

```c
typedef struct {
    uint64_t l[3];   // l[0]=bits 0-63, l[1]=bits 64-127, l[2]=bits 128-183
} int184_t;
```

`middle = target + |k|·d`（k ≤ 0 时等价于加法）用 `unsigned __int128` 实现：

```c
// kp = -k (non-negative)
uint64_t kp = /* ... */;

// kp * d in 184-bit (low bits only)
unsigned __int128 p0 = (unsigned __int128)kp * D[0];
uint64_t kd0 = (uint64_t)p0;
uint64_t carry0 = (uint64_t)(p0 >> 64);

unsigned __int128 p1 = (unsigned __int128)kp * D[1] + carry0;
uint64_t kd1 = (uint64_t)p1;
uint64_t carry1 = (uint64_t)(p1 >> 64);

unsigned __int128 p2 = (unsigned __int128)kp * D[2] + carry1;
uint64_t kd2 = (uint64_t)p2 & 0x00FFFFFFFFFFFFFFULL;

// middle = T + kd
unsigned __int128 s0 = (unsigned __int128)T[0] + kd0;
uint64_t r0 = (uint64_t)s0;
uint64_t c0 = (uint64_t)(s0 >> 64);
// ... 完成 r1, r2 ...
```

然后从 `(r2, r1, r0)` 中提取全部 23 个字节，逐字节查表校验是否在 `\w` 中。
